# Spendly Database Column Contract

**Status:** Approved physical-column baseline for the 30 entities in `DATABASE_SCHEMA.md`; only income source labels remain an owner decision. Exact state transitions must be defined before API implementation. This is documentation, not migration DDL.

This contract supplements the logical entity descriptions in `DATABASE_SCHEMA.md`. Unless a field is called nullable below, it is `NOT NULL`. Fields without a default have no database default and are supplied by the application. UUIDs are generated by the application. All foreign keys use `ON DELETE RESTRICT ON UPDATE RESTRICT`, unless explicitly stated otherwise; this preserves financial/audit history and immutable identifiers.

## Shared physical conventions

- UUID PK/FK: `BINARY(16)`. Python value is `uuid.UUID`; use one SQLAlchemy `TypeDecorator` over `BINARY(16)`, bind `UUID.bytes`, read `UUID(bytes=...)`. Alembic migration columns remain explicitly `BINARY(16)` and use the same stable custom type where model metadata is imported. Never use `bytes_le`, `CHAR(36)`, or mixed formats. Tests must cover UUID round-trips and migrated schema type inspection.
- Currency code: `CHAR(3) CHARACTER SET ascii COLLATE ascii_bin`; FK to `currencies.code`.
- Monetary amount: `DECIMAL(19,4)`; SQLAlchemy `Numeric(19, 4, asdecimal=True)`; Python `Decimal`; API decimal string. Positive amounts have `CHECK (amount > 0)`; signed account entries have `CHECK (amount_signed <> 0)`. Reject input exceeding currency `minor_unit_digits`; LKR/USD are 2; no silent rounding.
- Rate: `fx_rates.rate` is not money; its precision and scale remain deferred with FX implementation.
- Event instant: `DATETIME(6)` stored as UTC. `created_at DATETIME(6) NOT NULL DEFAULT CURRENT_TIMESTAMP(6)`. `updated_at DATETIME(6) NOT NULL DEFAULT CURRENT_TIMESTAMP(6) ON UPDATE CURRENT_TIMESTAMP(6)`. Nullable lifecycle instants are `DATETIME(6) NULL`.
- Calendar date: `DATE`; budget period start inclusive/end exclusive in the local calendar of the relevant space.
- Boolean: MySQL `BOOLEAN NOT NULL`, default stated per field (`FALSE`/`TRUE`).
- Structured preference/audit value: MySQL `JSON`.
- Enumerated state: `VARCHAR(n)` plus a named `CHECK` for values specified here. Use strings, not MySQL native `ENUM`, for migration compatibility. Reusable records use `ACTIVE`/`ARCHIVED`; budget periods use `OPEN`/`CLOSED`. Exact allowed transitions must be defined before API implementation. Domain-specific states retain their documented value sets.
- Where a reusable entity has no `status` column (`spaces`, `categories`), `archived_at IS NULL` represents `ACTIVE` and a non-null `archived_at` represents `ARCHIVED`; entities with both `status` and `archived_at` use the constrained `status` as the state and retain the timestamp for audit/display.
- Common timestamps `created_at` and `updated_at` are included on each entity where listed in the schema; other columns are not implicitly generated.

## Cross-row enforcement and owner decisions

Composite foreign keys enforce account-entry currency matching and transfer-entry ownership. MySQL row CHECKs enforce row-local shape only. Transaction services, within a database transaction and appropriate locks, enforce allocation scope/category compatibility, category kind, shared-Home-allocation requirements, explicit mixed-allocation consent, ownership authorization, entry signs, transfer balance, refund caps, allocation/payment/reservation aggregate limits, and forecast receipt totals. Goal contribution amount/currency/scope must match its linked reservation and goal. These constraints are not replaced by client validation.

Sharing is creator-controlled: authorize changes by comparing the principal with `financial_transactions.created_by_user_id`; record status/consent changes in `audit_events`. No separate projection table is required. Personal spaces are private; household spaces are visible to active members, but transactions remain private until explicitly shared. Household API projection allowlist: transaction ID (opaque reference), Home allocation amount, its currency code, transaction calendar date, description, and category display name. Do not return transaction total, account ID/name/type/balance, personal allocations, beneficiary/private fields, notes, unrelated history, or the full ORM object. A transaction marked shared must have an allocation to a Home space; when any Personal allocation also exists, `mixed_allocation_consent_at` must be set by the creator before sharing. Any allocation change clears consent and atomically returns sharing to `PRIVATE`; fresh creator consent is required to share again.

Posted corrections remain atomic void plus replacement; the `/void` endpoint must not create a posted void-only path.
