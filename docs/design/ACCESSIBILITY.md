# Accessibility Requirements

Target WCAG 2.2 AA as the design and implementation goal, with a practical manual QA process.

## Requirements

- Semantic HTML and correct heading structure.
- All functions usable with keyboard.
- Visible focus indicators.
- Accessible labels and instructions for every input.
- Errors identified in text and associated with fields.
- Sufficient contrast for text, controls and focus.
- Do not use color alone to communicate financial state.
- Charts provide summaries and accessible tabular alternatives.
- Dialogs manage focus and return focus on close.
- Screen-reader announcements for save/error status.
- Touch targets should be comfortably usable.
- Respect reduced-motion settings.
- Support browser zoom and reflow.
- Avoid time-limited tasks unless user can extend them.

## Financial accessibility

- Read currency and sign clearly.
- Do not rely on color to distinguish income/expense.
- Explain abbreviations.
- Provide exact numeric data behind visual charts.
- Ensure large values do not clip or become ambiguous.

## Testing

Include keyboard-only checks, screen-reader spot checks, contrast analysis, zoom/reflow checks, reduced-motion checks and automated accessibility scans. Automated scans do not replace manual testing.
